# Автопилот, который работает с закрытым ноутбуком

## Сначала — самый короткий путь

Если у тебя подключён **Postiz с каналом Threads**, половина этого документа тебе не нужна.
Postiz публикует из своего облака: агент ставит посты в расписание, дальше ноутбук
может быть закрыт неделю.

```
ТЫ (раз в 3–5 дней, 20 минут)      POSTIZ (облако, всегда)
  пополнила банк медиа        →      публикует по расписанию
  собрала план на 3–5 дней    →      ноутбук не нужен
  утвердила, агент поставил
```

Банк медиа при этом всё равно нужен: `uploadFromUrlTool` принимает **публичную ссылку**,
а не файл с диска. Банк её и даёт.

GitHub Actions ниже — для тех, кто не хочет платить за Postiz после триала,
или кому нужен Graph API ради ответов и аналитики.

---

## Честная картина: что можно, а что нет

Систему надо разделить на две части — они требуют разного.

| Часть | Нужна ли модель | Где может жить |
|---|---|---|
| **Публикация** по слотам | нет, это обычный скрипт | Postiz (своё облако) или GitHub Actions |
| **Продление токена**, проверка квоты | нет | GitHub Actions |
| **Генерация текстов**, план, ответы на комментарии | да, нужен Claude | локально или облачная routine |
| **Заливка медиа с твоего диска** | нет, но нужен доступ к диску | **только локально** |

Из этого следует главное правило:

> **Медиа заливается заранее, пока компьютер включён. В очереди лежит не файл, а ссылка.**

Ни GitHub Actions, ни облачный агент не видят твой рабочий стол. Поэтому фото и видео
надо один раз в несколько дней «сдать в банк» — дальше система крутит их сама.

## Архитектура

```
ТВОЙ MAC (когда включён)
  ├─ кидаешь фото/видео в ~/Claude/threads/inbox/
  ├─ «пополни банк медиа» → ffmpeg жмёт, режет EXIF, кладёт в репо
  ├─ «собери план на 3 дня» → тексты + подобранные медиа → очередь
  └─ git push  →  всё улетает в репозиторий threads-cloud

GITHUB (работает всегда, бесплатно)
  ├─ media/            отдаётся через CDN jsDelivr — это и есть публичные URL
  ├─ queue/queue.jsonl что и когда публиковать
  └─ Actions каждый час: публикует то, у чего подошёл слот, и коммитит статусы обратно

ОБЛАЧНЫЕ ROUTINES (нужен Claude, работают без Mac)
  ├─ ночная генерация текстов на завтра
  ├─ цикл ответов на комментарии
  └─ недельный разбор статистики
```

## Шаг 1. Репозиторий threads-cloud

Публичный — потому что медиа должны отдаваться по открытой ссылке
(они всё равно станут публичными, как только уйдут в пост). Токен в коде **не лежит**,
он в защищённых Secrets.

```bash
gh auth login
mkdir -p ~/Claude/threads-cloud/{media,queue,scripts}
cd ~/Claude/threads-cloud
PLUGIN=$(ls -d ~/.claude/plugins/cache/prime-threads/prime-threads-system/*/ | tail -1)   # путь установленного плагина
cp $PLUGIN/scripts/{threads_api.py,queue.py} scripts/
cp -R $PLUGIN/cloud/.github .
printf '.env\n*.log\n' > .gitignore
git init -b main && git add -A && git commit -m "threads cloud"
gh repo create threads-cloud --public --source=. --push
```

Если не хочешь публичный репозиторий — сделай `--private`, а медиа выложи отдельно:
статический проект на Vercel или бакет Cloudflare R2. В `media.config.json` тогда
`"cdn": "custom"` и `"cdn_base": "https://твой-домен/media"`.

## Шаг 2. Секреты

GitHub → репозиторий → **Settings → Secrets and variables → Actions → New repository secret**:

- `THREADS_ACCESS_TOKEN` — долгий токен из `GRAPH-API.md`
- `THREADS_USER_ID`

Проверь: вкладка **Actions** → workflow `publish-threads` → **Run workflow**.
Очередь пуста, поэтому он должен отработать зелёным и написать «нечего публиковать».

## Шаг 3. Расписание

В `.github/workflows/publish.yml` строка `cron: "5 6-20 * * *"`.

**Время в GitHub Actions всегда UTC.** Пересчитай под ядро аудитории:

| Твоё время (Киев, летом UTC+3) | UTC |
|---|---|
| 09:00–23:00 | `5 6-20 * * *` |
| 08:00–22:00 | `5 5-19 * * *` |

Цюрих летом UTC+2, зимой UTC+1 — сдвиг придётся править дважды в год.
GitHub может задержать запуск на 5–15 минут при нагрузке, поэтому окно в скрипте — 35 минут.

## Шаг 4. Конфиг банка медиа

`~/Claude/threads/media.config.json`:

```json
{
  "repo_path": "~/Claude/threads-cloud",
  "repo_slug": "ТВОЙ_GITHUB_НИК/threads-cloud",
  "branch": "main",
  "cdn": "jsdelivr"
}
```

## Как это выглядит в жизни

**Раз в 3–5 дней, 15 минут, при включённом Mac:**

1. Скидываешь в `~/Claude/threads/inbox/` всё, что насобиралось: скрины дашбордов,
   фото с телефона, куски рилсов, записи экрана.
2. В чате: **«пополни банк медиа»**. Агент сожмёт под требования Threads,
   срежет EXIF с геолокацией, посмотрит каждый файл и проставит теги и описание.
3. В чате: **«собери план на 3 дня»**. Тексты пишутся, медиа подбирается из банка
   по тегам (и не повторяется — берётся наименее использованное).
4. Смотришь таблицу, правишь хуки, утверждаешь.
5. **«отправь в облако»** — один `git push`.

**Дальше три дня ничего не делаешь.** GitHub публикует по слотам, даже если
ноутбук закрыт, ты в самолёте или спишь.

## Генерация и ответы без Mac

Публикацию закрывает GitHub. Для генерации и ответов нужен Claude — здесь два варианта.

**Вариант 1: облачные routines** (скилл `schedule`). Работают без включённого Mac.
Ограничение: у облачного агента нет доступа к твоему диску, поэтому он берёт медиа
только из банка — то есть банк должен быть пополнен заранее. Для текстовых постов
ограничения нет вообще.

**Вариант 2: работать пачками.** Раз в 3–5 дней набиваешь очередь на несколько дней
вперёд с запасом. Проще, дешевле и надёжнее — и это то, с чего стоит начинать.

**Ответы на комментарии** — самое ценное и самое «живое». Первый месяц лучше отвечать
самой или подтверждать черновики: у ответов голос слышнее, чем у постов, и именно
по ним аудитория решает, живой ты человек или бот.

## Если всё-таки хочется, чтобы работал сам Mac

Ноутбук с закрытой крышкой засыпает и cron не срабатывает. Не спит только если:
- подключено питание,
- в **Системные настройки → Аккумулятор → Питание от сети** включено
  «Не давать компьютеру автоматически засыпать, когда дисплей выключен»,
- подключён внешний монитор или запущен `caffeinate -s`.

Это работает, но ломается от любой мелочи: закрыла крышку без питания, ушла в кафе,
перезагрузка после обновления. **GitHub Actions надёжнее и бесплатно** — используй его
как основной канал, а локальный cron только как дубль.

## Что проверять раз в неделю

- Вкладка **Actions**: все запуски зелёные?
- `python3 scripts/queue.py stats` — сколько осталось в очереди
- `python3 scripts/media_bank.py list --unused` — не кончается ли банк медиа
- `python3 scripts/threads_api.py limits` — остаток суточной квоты
- Срок токена (60 дней, задача `token-check.yml` пишет на почту)
