# Threads Graph API — подключение шаг за шагом

Займёт 20–30 минут один раз. Всё бесплатно. Ничего программировать не надо —
есть скрипт-помощник, который делает всю техническую часть.

**Что ты получишь:** право публиковать 250 постов и 1000 ответов в сутки от своего
имени, читать комментарии и статистику каждого поста. Без этого система работает
как «пишет и складывает», а не как автопилот.

---

## Шаг 1. Создать приложение Meta

1. Открой [developers.facebook.com/apps](https://developers.facebook.com/apps).
   Войди тем аккаунтом Facebook/Instagram, к которому привязан твой Threads.
2. Если это первый раз — Meta попросит подтвердить аккаунт разработчика:
   номер телефона и почта. Это бесплатно.
3. **Create app** → в поле «What do you want your app to do?» выбери **Threads API**
   (может называться «Access the Threads API» или «Threads Use Case»).
4. Название приложения: любое, например `Prime Threads`. Тип — не бизнес, обычное.
5. Готово, ты в дашборде приложения.

> **Важно.** Ты получишь **две пары** ID и секрета: обычные App ID/Secret и **Threads
> App ID / Threads App Secret**. Нужны именно **Threads**-версии. Они лежат в разделе
> **Use cases → Threads API → Settings**, либо в **App settings → Basic**, в блоке Threads.

---

## Шаг 2. Включить права

Раздел **Use cases → Threads API → Customize** (или **Permissions**).

Включи (кнопка Add / Request рядом с каждым):

| Право | Зачем |
|---|---|
| `threads_basic` | обязательно для всех запросов |
| `threads_content_publish` | публиковать посты |
| `threads_manage_replies` | отвечать на комментарии |
| `threads_read_replies` | читать комментарии |
| `threads_manage_insights` | статистика постов и аккаунта |

Опционально: `threads_keyword_search` — поиск постов по ключевым словам,
пригодится скиллу `threads-swipe` для разведки ниши.

**Пока приложение в режиме Development этих прав достаточно для твоего аккаунта.**
Ревью Meta нужно только чтобы работать с чужими аккаунтами — тебе не нужно.

---

## Шаг 3. Добавить свой аккаунт как тестировщика

Это место, где чаще всего застревают. Два действия в двух разных местах.

**На стороне Meta:**
1. В дашборде приложения → **App roles → Roles** → **Add people**.
2. Выбери роль **Threads Tester**.
3. Введи свой **ник в Threads** (не почту) → отправь приглашение.

**На стороне Threads:**
4. Открой Threads (приложение или threads.net) под этим аккаунтом.
5. **Настройки → Аккаунт → Сайты и приложения** (в английской версии
   *Settings → Account → Website permissions → Invites*).
6. Прими приглашение от своего приложения.

Проверка: в App roles напротив твоего ника должно стоять **Accepted**, а не Pending.

---

## Шаг 4. Прописать redirect URI

Раздел **Use cases → Threads API → Settings**, поле **Redirect Callback URLs**.

Впиши: `https://localhost/`

Он никуда не ведёт и не должен — мы просто заберём код авторизации из адресной
строки браузера. Сервер поднимать не нужно. Сохрани.

---

## Шаг 5. Получить токен

Скопируй из дашборда **Threads App ID** и **Threads App Secret**.

Скрипты лежат внутри установленного плагина. Один раз в терминале задай путь к нему
(проще всего спросить в чате Claude: «покажи $CLAUDE_PLUGIN_ROOT»):

```bash
PLUGIN=$(ls -d ~/.claude/plugins/cache/prime-threads/prime-threads-system/*/ | tail -1)
```

**5.1. Собрать ссылку авторизации:**

```bash
python3 $PLUGIN/scripts/get_token.py url --app-id ТВОЙ_THREADS_APP_ID
```

Скрипт напечатает длинную ссылку. Открой её в браузере, где залогинен нужный
Threads-аккаунт. Подтверди доступ ко всем правам.

**5.2. Забрать код.** Браузер уйдёт на `https://localhost/?code=AQB...#_` и покажет
ошибку «сайт недоступен» — так и должно быть. Скопируй из адресной строки всё, что
идёт после `code=`, **без хвоста `#_`**.

**5.3. Обменять на долгий токен:**

```bash
python3 $PLUGIN/scripts/get_token.py exchange \
  --app-id ТВОЙ_THREADS_APP_ID \
  --secret ТВОЙ_THREADS_APP_SECRET \
  --code ВСТАВЬ_КОД
```

Скрипт сам сделает два обмена (часовой токен → 60-дневный), проверит аккаунт и
напечатает готовые две строки.

**5.4. Сохранить:**

```bash
nano ~/Claude/threads/.env
```
```
THREADS_ACCESS_TOKEN=THAA...
THREADS_USER_ID=1234567890
```

```bash
chmod 600 ~/Claude/threads/.env
```

> Секрет приложения нигде не сохраняется — он нужен только в момент обмена.
> Токен не показывай никому и не клади в git: он даёт полный доступ к публикации.

---

## Шаг 6. Проверить

```bash
python3 $PLUGIN/scripts/threads_api.py me
```
Должен вернуть твой id и ник.

```bash
python3 $PLUGIN/scripts/threads_api.py limits
```
Должен показать `quota_usage: 0` и `quota_total: 250`.

**Первый живой пост** — только когда сама решишь:
```bash
python3 $PLUGIN/scripts/threads_api.py post --text "тест"
```

---

## Продление токена

Токен живёт **60 дней**. Продлевать можно начиная с 24 часов после выдачи.

```bash
python3 $PLUGIN/scripts/get_token.py refresh --token ТЕКУЩИЙ_ТОКЕН
```

Новый токен впиши и в `.env`, и в GitHub Secrets (если настроена облачная публикация).
Задача `token-check.yml` раз в месяц напомнит письмом.

Если токен всё-таки протух — просто повтори шаг 5, приложение пересоздавать не нужно.

## Если что-то не работает

| Что видишь | Причина | Что делать |
|---|---|---|
| `Invalid platform app` при авторизации | взят обычный App ID вместо Threads App ID | взять ID из блока Threads |
| `redirect_uri` mismatch | не совпал URI | в ссылке и в настройках должно быть одинаково, вместе со слешем: `https://localhost/` |
| код не принимается | код одноразовый и живёт минуты | заново открыть ссылку из шага 5.1 |
| `(#190) Invalid OAuth access token` | токен истёк или не хватает прав | продлить или получить заново |
| `(#100)` при публикации | не тот `THREADS_USER_ID` | взять id из ответа `me` |
| приглашение тестировщика не приходит | введена почта вместо ника | вводить именно ник в Threads |
| приняла приглашение, всё равно нет доступа | Meta кэширует | подождать 5–10 минут, перевыпустить токен |
| контейнер медиа `ERROR` | ссылка на медиа не публичная | проверить URL в режиме инкогнито |
