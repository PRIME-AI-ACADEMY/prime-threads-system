# Threads SMM Plan — план от специалиста в расписание

Этот скилл для случая, когда план пишет **человек**, а не система: SMM-специалист,
ассистент или сама владелица аккаунта в таблице. Задача скилла — дать формат,
проверить результат и поставить его в расписание без ручного перебивания.

Если план должна собрать система сама — это `threads-plan`, не этот скилл.

---

## 1. Отдать материалы специалисту

Два файла, оба лежат в плагине:

- **`${CLAUDE_PLUGIN_ROOT}/GUIDE-SMM.md`** — полный гайд: ритм, окна, набор дня,
  форматы под цель, 8 типов хуков, правила текста, red lines, чек-лист эмоций
  и описание формата сдачи. Это то, что читает специалист.
- **`${CLAUDE_PLUGIN_ROOT}/templates/content-plan-template.csv`** — шаблон таблицы
  с заполненной строкой-примером.

Создать свежий шаблон в удобном месте:
```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/import_plan.py --template ~/Desktop/threads-plan.csv
```

Если специалисту удобнее Google-таблица — пусть создаст её с теми же колонками
и потом выгрузит в CSV (Файл → Скачать → CSV).

### Колонки

| Колонка | Что внутри | Обязательно |
|---|---|---|
| `date` | `2026-10-20` | да |
| `time` | `07:30`, по часовому поясу аудитории | да |
| `goal` | подписки / охваты / продажи | нет, но желательно |
| `rubric` | название рубрики | нет |
| `hook_type` | результат, действие, интрига, боль, обещание, позиция, отрезвление, выгода | нет |
| `title` | рабочее название ветки | да |
| `post` | текст открывающего поста | да |
| `c1`…`c5` | комментарии ветки по порядку | нет |
| `media` | публичная ссылка на фото или видео | нет |
| `event` | `да`, если ветка зовёт на событие | нет |

`goal` и `hook_type` формально необязательны, но без них не работают проверки
ритма (баланс целей, повтор типа хука подряд). Проси заполнять.

## 2. Принять и проверить план

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/import_plan.py <файл> --tz Europe/Kyiv
```

Часовой пояс — по ядру аудитории. Переход на зимнее и летнее время скрипт
пересчитывает сам, вручную ничего сдвигать не надо.

Вывод делится на три части, и относиться к ним надо по-разному:

**Ошибки разбора** — строка не прочиталась (битая дата, нет текста поста).
Такие строки в план не попадают вообще. Чинить обязательно.

**Нарушения правил** — длина больше 500 видимых знаков, «не X, а Y» в любом
из семи вариантов, длинное тире, ИИ-лексика, два хештега, ссылка в открывающем
посте, список-тред без пункта 1, ветка про событие без ссылки или без слова
«бесплатно». Чинить обязательно: это то, что душит охват.

**Замечания по ритму** — больше 8 веток в день, пауза между ветками меньше
20 минут, два одинаковых типа хука подряд, все ветки дня на одну цель, за весь
план ни одной ветки на продажи. Это не ошибки, а повод посмотреть. Решает человек.

### Как подавать правки

Не вываливай сырой вывод скрипта. Собери по каждой проблемной ветке:
что именно нарушено, **почему это важно** и готовый исправленный вариант.
Специалисту нужно понять правило, а не просто переписать строку.

Для правки текста используй скилл `threads-write`: он знает голос, 8 типов хуков,
13 формул и прогоняет те же проверки.

## 3. Поставить в расписание

Сначала **черновиками**, всегда:

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/import_plan.py <файл> \
  --tz Europe/Kyiv --postiz <integrationId> --out payloads.json
```

`integrationId` канала Threads берётся из `integrationList` (запись с
`platform: "threads"`). Скрипт складывает готовые payload с `type: "draft"`.

Дальше отправляй их по одному через `integrationSchedulePostTool`, показывай,
что создалось, и **только после явного «да»** меняй `type` на `"schedule"`
и ставь по-настоящему.

Подробности режима публикации — скилл `threads-publish`.

### Обязательный шаг после постановки

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/queue.py log --file <файл с ветками> --channel postiz
```

Без этого проверка свежести слепа: через пару недель система начнёт предлагать
темы, которые уже выходили.

---

## 4. Чего делать нельзя

- Ставить план в расписание, пока есть нарушения правил.
- Публиковать без явного подтверждения человека.
- Молча править тексты специалиста: показывай правку и причину, решение за человеком.
- Выдумывать цифры и кейсы, если в плане стоит заглушка. Спрашивай.

## 5. Что сказать специалисту про ежедневную работу

План закрывает публикации. Три вещи остаются руками, и без них план не сработает:

1. ответы на свои комментарии в первые 30 минут после выхода ветки;
2. 5–10 осмысленных комментариев в день под чужими ветками своей аудитории;
3. раз в две недели — снять статистику (скилл `threads-analytics`).

Файлы: `${CLAUDE_PLUGIN_ROOT}/GUIDE-SMM.md`,
`${CLAUDE_PLUGIN_ROOT}/references/rhythm-windows.md`, `formats-by-goal.md`,
`hooks-ru.md`, `examples.md`
