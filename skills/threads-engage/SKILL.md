# Threads Engage — движок ответов

Это **самый недооценённый и самый мощный** блок системы. Ответ автора на реплай
алгоритм считает тяжелее самого реплая. Пост, под которым автор отвечает в первые
30 минут, получает кратно больше раздачи.

## Режим работы: с Graph API и без него

| | Без Graph API (по умолчанию) | С Graph API |
|---|---|---|
| Где читаешь комментарии | в приложении Threads, сама | агент тянет через API |
| Кто пишет ответ | агент готовит черновик по твоему голосу, ты отправляешь | агент может отправить сам |
| Напоминания | задача по расписанию «проверь комментарии» | автоматический цикл |

**Без API это не хуже по результату, просто требует твоих десяти минут.**
Главное здесь не автоматизация, а скорость: ответ в первые 30 минут стоит дороже
любого текста, который агент напишет за тебя.

Рабочий приём без API: скидываешь в чат скриншот комментариев или копируешь текст,
агент возвращает 3–5 готовых ответов твоим голосом, ты вставляешь.

## Цикл A — ответы под своими постами (каждые 20–30 минут)

**Без API:** открой Threads, посмотри новые комментарии под ветками за последние
два часа, скинь их сюда текстом или скриншотом.

**С API:**
```bash
# последние посты
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/threads_api.py mine --limit 10
# комментарии к посту
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/threads_api.py replies --to <media_id>
# ответ
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/threads_api.py reply --to <reply_id> --text "..."
```

**Приоритет ответов:**
1. Вопросы (превращаются и в ответ, и в тему для нового поста).
2. Развёрнутые комментарии (5+ слов) — на них отвечать длиннее, это продолжает диалог.
3. Несогласие — отвечать тепло и по существу, спор в комментариях = топливо охвата.
4. Короткие «класс», «согласна» — лайк или короткий тёплый ответ, без формальностей.
5. Хейт/токсичность — не отвечать, **блокировать**. Не спорить и не кормить.
   Отдельное правило практиков: не ссать высказываться и не обсирать клиентов.

**Как отвечать (правила):**
- Голосом из `voice.md`, а не «Спасибо за ваш комментарий!».
- Ответ должен добавлять что-то: цифру, пример, уточняющий вопрос.
- **Заканчивай вопросом** там, где уместно — это второй виток диалога.
- Длина: 1–3 строки. Ответ длиннее поста выглядит странно.
- Никогда не переводи в продажу в первом ответе. Сначала польза, потом «могу разобрать подробнее».
- ❌ Не отвечай шаблоном. Три одинаковых ответа подряд видны и читаются как бот.

**Режим контроля:** по умолчанию агент **готовит черновики ответов и показывает списком**,
человек говорит «отправляй». Полный автомат включается явной командой пользователя
и только после недели проверенных черновиков.

## Цикл B — комментинг чужих веток. НОРМА: 5–10 В ДЕНЬ

Это не «по возможности», а ежедневная норма, равная по важности самим публикациям.

Механика, которую называют практики: **после того как ты откомментировала чью-то ветку,
ты появляешься в ленте этого человека**. Комментинг не тратит твою суточную квоту
публикаций и даёт охват почти бесплатно.

**Где комментировать:** список аккаунтов из `bank/swipe.md`, посты не старше 1–2 часов
(поздний комментарий никто не увидит).

**Что писать:**
- Добавь свой опыт или цифру, которой нет в посте.
- Или мягко не согласись и объясни, почему.
- Или задай вопрос, на который автор захочет ответить.
- 1–3 строки. Без ссылок. Без «отличный пост!». Без саморекламы.

**Тест перед отправкой:** если этот комментарий мог написать кто угодно — не отправляй.

## Цикл C — сбор тем из комментариев

Каждый вопрос из комментариев и директа дописывай в `~/Claude/threads/bank/topics.jsonl`
со `"source": "question"` и скором +2. Это самые конверсионные темы:
их уже подтвердила аудитория.

## Метрика блока

Считать еженедельно:
- доля своих веток, где автор ответил в первые 30 минут (цель: **100%**),
- комментариев под чужими ветками в день (цель: **5–10**),
- среднее число комментариев на пост (цель: **≥ 3**, здоровый рост — вверх неделя к неделе),
- сколько тем в банк пришло из комментариев (цель: **≥ 5 в неделю**).

Лимит API: **1000 ответов в сутки** — упереться практически невозможно.
