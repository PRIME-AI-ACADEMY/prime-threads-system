# Threads Start — с чего начать

Этот скилл ведёт пользователя за руку. Он ничего не делает сам: он проверяет
состояние, называет следующий шаг и запускает нужный скилл.

## 1. Диагностика (всегда первым делом)

Проверь молча и покажи одной таблицей:

```bash
ls ~/Claude/threads/profile/ 2>/dev/null          # есть ли ДНК и голос
ls ~/Claude/threads/bank/ 2>/dev/null             # есть ли темы и банк хуков
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/queue.py stats
```
Плюс `integrationList` (Postiz) — подключён ли канал Threads.

| Шаг | Что проверяем | Готово? |
|---|---|---|
| 1. Канал публикации | Postiz с каналом threads | да / нет |
| 2. ДНК аккаунта | `profile/dna.md`, `profile/voice.md` | да / нет |
| 3. Разведка ниши | `bank/swipe.md`, `bank/hooks.md` | да / нет |
| 4. Банк тем | `bank/topics.jsonl`, ≥ 20 тем | да / нет |
| 5. План | очередь или журнал публикаций | да / нет |

**Называй ровно один следующий шаг**, а не весь список сразу. Человек, которому
выдали двенадцать скиллов, не делает ничего.

## 2. Маршрут

### Шаг 1 — канал публикации (5 минут)
Postiz с подключённым каналом Threads. Проверка: `integrationList` должен вернуть
запись с `platform: "threads"`.
Нет — отправь подключать: Postiz → Add channel → Threads.
Дальше → скилл `threads-setup` (создаст рабочую папку).

Graph API на этом шаге **не нужен**. Он даёт автоответы и автоматическую статистику,
но это отдельная надстройка (`GRAPH-API.md`), к ней возвращаемся позже.

### Шаг 2 — ДНК аккаунта (15 минут, самый важный)
Скилл `threads-dna`. Без него система пишет обобщённо.
Если у пользователя уже есть `~/Claude/business-dna.md`, `audience.md`,
`tone-of-voice.md` — переиспользуй их, не спрашивай заново.

Результат: `profile/dna.md`, `voice.md`, `funnel.md`, `rubrics.md` + название
серийной рубрики.

### Шаг 3 — разведка ниши (20 минут)
Скилл `threads-swipe`. Спроси 2–5 аккаунтов, на которые она равняется.
Результат: банк хуков и понимание, какие форматы в нише работают.

### Шаг 4 — темы (15 минут)
Скилл `threads-radar`. Норма за проход: 20–40 тем со скором ≥ 6.

### Шаг 5 — план на три дня
Скилл `threads-plan`. Ритм для старта — **6 веток в день, 6 дней в неделю**
(`references/rhythm-windows.md`). Не 20: резкий разгон на молодом аккаунте
даёт муты и просадку.

Покажи план таблицей, дождись правок, и только потом дальше.

### Шаг 6 — первая публикация
Скилл `threads-publish`, режим Postiz. **Первый прогон — всегда черновик**
(`type: "draft"`), показать, что создалось, и только после «ок» ставить `schedule`.

После постановки обязательно:
```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/queue.py log --channel postiz --file <файл>
```

### Шаг 7 — что делать руками каждый день
Скажи прямо, эти три вещи система не сделает:
- отвечать на комментарии в первые 30 минут после ветки;
- 5–10 осмысленных комментариев под чужими ветками своей ниши;
- раз в 1–2 недели снимать статистику (скилл `threads-analytics`).

## 3. Правила ведения

- **Один шаг за раз.** Закончили — покажи, что получилось, и назови следующий.
- Не переходи к следующему шагу, пока предыдущий не дал файл или результат.
- Если пользователь хочет прыгнуть сразу к публикации — предупреди один раз,
  что без ДНК тексты будут обобщёнными, и делай как просит.
- Ничего не публикуй без явного «да».

## 4. Куда идти дальше

| Хочу | Скилл |
|---|---|
| писать отдельные ветки | `threads-write` |
| добавить фото и видео | `threads-media-bank`, `threads-visual` |
| отвечать на комментарии | `threads-engage` |
| посчитать, что сработало | `threads-analytics` |
| поставить на расписание | `threads-autopilot` |
| автоответы и автостатистику | `GRAPH-API.md`, затем `threads-setup` режим B |

Справочники: `${CLAUDE_PLUGIN_ROOT}/references/rhythm-windows.md` (окна и ритм),
`formats-by-goal.md` (форматы под цель), `examples.md` (восемь разобранных веток).
