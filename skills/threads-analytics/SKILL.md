# Threads Analytics — обучение на своих данных

Через месяц система должна писать под **её** аудиторию, а не по общей теории.
Этот скилл замыкает контур обратной связи.

**Graph API для этого не нужен.** Цифры снимаются вручную раз в 1–2 недели,
считает их скрипт. Автоматический режим через API есть, но он опциональный.

---

## 1. Три способа снять цифры

### Режим A — скриншоты (по умолчанию, работает у всех)

Что нужно: приложение Threads на телефоне. Ничего настраивать не надо.

1. Threads → своя ветка → **«Просмотры»** под постом → открывается «Взаимодействия».
   Там: просмотры, лайки, ответы, репосты, цитаты, а внизу блок «Профиль» с подписками.
2. Скриншот. Повторить по веткам за период (обычно 12–20 штук за две недели,
   хватает топ-10 и худших 5, снимать все не обязательно).
3. Скинуть скриншоты в чат.

Агент читает цифры со скриншотов и раскладывает по полям. **Ничего не выдумывает:**
если метрики на скрине нет, поле остаётся пустым.

### Режим B — браузер (быстрее, но только для себя)

Если подключён Claude in Chrome и в нём открыт залогиненный threads.com:
агент сам обходит последние ветки и читает статистику со страницы.

Правила:
- работать только с уже открытой сессией пользователя, ничего не публиковать;
- если разметка изменилась и цифры не читаются — честно сказать и перейти в режим A,
  а не угадывать.

Для учеников этот режим не обязателен: у них может не быть расширения.

### Режим C — Graph API (полный автомат, опционально)

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/threads_api.py mine --limit 100 --since 2026-09-01
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/threads_api.py insights --media <media_id>
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/threads_api.py account-insights --since 2026-09-01
```

Настройка — `GRAPH-API.md`. Дальше всё то же самое: цифры идут в тот же журнал.

## 2. Как записать замеры

Заготовка со списком уже опубликованных веток:

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/stats_log.py template --days 14
```

Она подтягивает из журнала публикаций `id`, тему и слот. Остаётся проставить цифры:

```json
{"id": "1-07:30", "views": 39400, "likes": 338, "replies": 40,
 "reposts": 10, "shares": 107, "follows": 88}
```

`views` обязателен, остальное — что видно. Записать:

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/stats_log.py add --file measures.json
```

Скрипт сам подтянет из журнала формулу, рубрику, окно, цель и лендинг — их
переписывать руками не надо.

> Если журнал публикаций пуст, значит ветки ставились мимо очереди. Почини это:
> после каждой постановки в Postiz делай `queue.py log --channel postiz`.

## 3. Пересчёт весов

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/stats_log.py weights
```

Что считается:

```
engagement_score = replies*30 + shares*5 + reposts*3 + quotes*3 + likes
er               = engagement_score / views
subs_per_1k      = follows / views * 1000
вес среза        = средний ER среза / средний ER аккаунта
```

Веса пишутся в `~/Claude/threads/memory/patterns.json` по срезам: формула, рубрика,
**окно** (утро / день / прайм / перед сном), цель, подписки на 1000 просмотров
по рубрикам, лучшие и худшие часы.

**Срез меньше 5 постов игнорируется** — это шум, и скрипт прямо пишет об этом в `notes`.

`threads-write` и `threads-plan` читают этот файл: формулы с весом > 1.2 идут
в приоритет, с весом < 0.7 — не чаще одного раза на 20 веток.

## 4. Отчёт

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/stats_log.py report --weeks 2
```

Выдаёт суммы, средний ER, топ-5 и худшие 3 ветки. Дальше **агент дописывает
смысловую часть**, которую скрипт посчитать не может:

```
ЧТО СРАБОТАЛО: {формулы, рубрики, окна с весом > 1.2} — и гипотеза почему
НЕ СРАБОТАЛО:  {вес < 0.7} — и гипотеза почему
ВОРОНКА:       клики в профиль, новые подписчики в Telegram, заявки (из её данных)
РЕШЕНИЯ НА СЛЕДУЮЩИЙ ПЕРИОД (3–5 штук, конкретных)
```

Сохранить в `~/Claude/threads/memory/weekly/YYYY-WW.md`.

**Отчёт без решений бесполезен.** Каждый вывод обязан превратиться в изменение:
в `patterns.json`, в колесе рубрик или в сетке слотов.

## 5. Что считать главным

Не просмотры.

| Метрика | Почему она важнее охвата |
|---|---|
| **Подписки на 1000 просмотров** | охват без подписок аккаунт не растит |
| **Отправки в личку** | на практике их бывает в 10 раз больше репостов (107 против 10 при 39 400 просмотров) — это главный канал распространения |
| **Комментарии на ветку** | самый тяжёлый сигнал ранжирования |

Ожидаемая картина: личные истории дают самый большой охват, а списки и советы дают
подписки. Если у неё не так — это ценная находка, записать в `notes`.

## 6. Тревожные сигналы

| Симптом | Причина | Действие |
|---|---|---|
| Просмотры падают период к периоду | усталость, повтор тем | усилить ротацию, снизить частоту на 25% |
| Просмотры есть, комментариев нет | посты закрывают мысль | больше T3/T9/T1, вопрос в финале |
| Комментарии есть, подписок нет | непонятно, чем полезна дальше | переписать шапку и закреп, добавить рубрику-разбор |
| Подписки есть, заявок нет | сломана воронка | `funnel.md`: CTA, лид-магнит, закреп |
| Резкий обвал всего | red line или спам-флаг | проверить последние 10 веток по `algorithm-2026.md` |

## 7. Регулярность

Раз в две недели. Ставится задачей по расписанию (скилл `schedule` или
`mcp__scheduled-tasks`), промпт самодостаточный:

```
Скилл threads-analytics. Собери замеры за 14 дней:
1) stats_log.py template --days 14 — покажи список веток пользователю
2) попроси скриншоты статистики (или прочитай из браузера, если есть Chrome)
3) stats_log.py add, потом weights
4) stats_log.py report --weeks 2 + смысловая часть и 3–5 решений
5) сохрани отчёт в memory/weekly/
Ничего не выдумывай: нет цифры — оставь поле пустым.
```

Файлы: `${CLAUDE_PLUGIN_ROOT}/references/algorithm-2026.md`, `rhythm-windows.md`,
`formats-by-goal.md`, `funnel.md`
