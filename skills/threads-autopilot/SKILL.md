# Threads Autopilot — четыре задачи, которые крутят систему

## Архитектура цикла

```
23:00  ГЕНЕРАЦИЯ    радар → план на завтра → тексты → визуал → очередь (draft)
08:00  УТВЕРЖДЕНИЕ  сводка дня в чат/уведомление → человек говорит «ок» → approve
каждый слот  ПУБЛИКАЦИЯ  queue.py publish-due
+30 мин      ОТВЕТЫ      threads-engage: комментарии под свежим постом
ВС 20:00     РАЗБОР      threads-analytics → patterns.json → отчёт
```

## Задача 0 — Пополнение банка медиа (раз в 3–5 дней, вручную)

Единственный шаг, который нельзя автоматизировать полностью: агент должен посмотреть
файлы глазами и снять приватные. Напоминай о нём, когда свободных медиа в банке < 10:
```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/media_bank.py list --unused
```

## Задача 1 — Ночная генерация (ежедневно 23:00)

Промпт задачи должен быть **самодостаточным** (cron-задача не помнит этот разговор):

```
Прочитай ~/Claude/threads/profile/*.md и ~/Claude/threads/memory/patterns.json.
1) Скилл threads-radar: набери 15–20 тем со скором ≥6, проверь свежесть 14 дней.
2) Скилл threads-plan: разложи по слотам на завтра по режиму из dna.md,
   соблюди ротацию рубрик и пропорцию 5-3-1-1.
3) Скилл threads-write: напиши текст на каждый слот, прогони 4 проверки, прогноз ≥7.
4) Скилл threads-visual: сделай медиа там, где формат требует.
5) Положи всё в очередь статусом draft. НИЧЕГО НЕ ПУБЛИКУЙ.
6) Напиши сводку дня в ~/Claude/threads/queue/tomorrow.md: время | рубрика | формула | хук | прогноз.
7) Если настроено облако: скопируй очередь в ~/Claude/threads-cloud/queue/ и сделай
   media_bank.py push — иначе GitHub не увидит новые посты.
```

## Задача 2 — Публикация (каждый час, 07:00–23:00)

**Режим Postiz (основной):** этой задачи нет. Ночная генерация сразу ставит утверждённые
посты в расписание Postiz (`type:"schedule"`), публикует облако Postiz.

**Режим Graph API:**
```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/queue.py publish-due --window 30
```

Публикует только `approved`. Если очередь пуста или всё ещё `draft` — **это не ошибка**,
задача тихо завершается. Логи: `~/Claude/threads/memory/publish.log`.

## Задача 3 — Ответы (каждые 30 минут, 08:00–23:00)

```
Скилл threads-engage, цикл A.
Возьми посты за последние 2 часа, собери новые комментарии,
подготовь ответы голосом из voice.md.
Режим по умолчанию: показать черновики и ждать «ок».
Раз в день дополнительно цикл B: 5–10 комментариев в ниши-аккаунтах из bank/swipe.md.
```

## Задача 4 — Недельный разбор (воскресенье 20:00)

```
Скилл threads-analytics: собери инсайты за 7 дней, пересчитай patterns.json,
запиши отчёт в memory/weekly/, выведи 3–5 конкретных решений на следующую неделю.
```

## Где что крутится (важно!)

| Задача | Нужна модель | Где живёт |
|---|---|---|
| Публикация по слотам | нет | **Postiz (своё облако) или GitHub Actions — оба работают с закрытым ноутбуком** |
| Продление токена, квота | нет | GitHub Actions |
| Генерация, план, ответы | да | локально пачками или облачные routines |
| Заливка медиа с диска | нет, но нужен диск | **только локально**, заранее |

Медиа надо сдавать в банк заранее: ни Actions, ни облачный агент не видят рабочий стол.
Полная схема — в `CLOUD.md`, скилл `threads-media-bank`.

## Как поставить

**Вариант 0a — Postiz (если подключён канал Threads):**
Ничего ставить не надо. Агент при ночной генерации сразу кладёт посты в расписание
Postiz (`type:"schedule"`), дальше публикует сам Postiz. Задачи 2 (публикация) не существует.

**Вариант 0b — GitHub Actions (если Postiz не используется):**
Готовые workflow лежат в `${CLAUDE_PLUGIN_ROOT}/cloud/.github/workflows/`.
Настройка — `CLOUD.md`. Это единственный способ публиковать, когда Mac выключен.

**Вариант 1 — локальный cron (только режим Graph API; работает пока Mac включён):**
В cron переменной `${CLAUDE_PLUGIN_ROOT}` нет — подставь реальный путь установленного плагина.
Узнать его: `echo $CLAUDE_PLUGIN_ROOT` в чате, обычно это
`~/.claude/plugins/cache/prime-threads/prime-threads-system/<версия>/`.
```bash
crontab -e
```
```
0 * * * *  /usr/bin/python3 <ПУТЬ_К_ПЛАГИНУ>/scripts/queue.py publish-due >> ~/Claude/threads/memory/publish.log 2>&1
```
Публикация — единственная задача, которую стоит вешать на голый cron: она не требует модели.
Остальные три ставятся как задачи Claude.

**Вариант 2 — задачи Claude (рекомендуется для 1, 3, 4):**
через `mcp__scheduled-tasks__create_scheduled_task` или скилл `schedule`.
Каждой задаче — самодостаточный промпт из блоков выше.

**Вариант 3 — облачные routines** (работают без включённого Mac), скилл `schedule`.

## Уровни автономии

| Уровень | Что делает сам | Что через человека |
|---|---|---|
| 1. Черновики | генерация, план, тексты | утверждение и публикация |
| 2. Дневное «ок» ⭐ | всё до публикации; постит утверждённое | одно «ок» утром на весь день |
| 3. Полный автомат | генерирует и публикует | недельный разбор |

**Начинать с уровня 1 минимум на неделю.** Переход на 3 — только после того, как
две недели подряд ничего не пришлось править вручную.

## Здоровье системы (проверять в задаче 1)

- Остаток квоты: `threads_api.py limits`.
- Срок токена: живёт 60 дней. За 7 дней до конца — предупредить.
  Продление: `GET https://graph.threads.net/refresh_access_token?grant_type=th_refresh_token&access_token=...`
- Записи `failed` в очереди — разобрать и перепоставить.
- Тем в банке меньше 10 → запустить радар вне очереди.
- Средний ER упал больше чем на 30% за неделю → снизить частоту, проверить red lines.

## Стоп-кран

Одна команда останавливает всё: перевести все `approved` в `draft`.
```bash
python3 -c "import json,io;p='$HOME/Claude/threads/queue/queue.jsonl';r=[json.loads(l) for l in open(p) if l.strip()];[i.__setitem__('status','draft') for i in r if i.get('status')=='approved'];open(p,'w').write(''.join(json.dumps(i,ensure_ascii=False)+'\n' for i in r))"
```
